# CX00–CX02 — Conversation Experience Reset

**Date:** 2026-09-14  
**Status:** CX00 PASS; CX01 PASS (automated); CX02 PASS (domain tests)

## CX00 current-state audit

The previous shell treated one recorded utterance as the primary interaction. `RecordButton_Click` creates a session and participant turn, optionally starts `RealtimeStreamingOrchestrator`, captures locally, and on a manual stop finalizes the Source and closes the turn/session. Realtime completion then stores derived speech, while ordinary speech playback was previously exposed only through a separate replay button. The next conversational turn required another manual start/stop cycle.

`OpenAiRealtimeStreamingProvider` and `OpenAiRealtimeWebSocketProvider` both configure `turn_detection = null`. The current transport therefore supports streamed or completed responses, but does not yet implement automatic end-of-turn detection or safe barge-in. Local capture remains authoritative and provider output remains derived audio; AI output is never participant evidence.

`App.xaml.cs` wires the existing transcription, Responses, speech output, Realtime, memory extraction, current-information, retry, archive, Family Admin, deletion, withdrawal, source playback, and application-lock services. No storage schema or provenance boundary was changed for this reset.

## CX01 participant/admin separation

The default shell now presents a calm participant surface with:

- greeting and one obvious `開始對話` control;
- visible conversational state and latest response text;
- a compact privacy indicator;
- a separate `停止對話` action while capture is active;
- collapsed `首次設定／私隱` controls;
- collapsed `家庭管理／診斷` controls.

The existing diagnostic pipeline, clarification authoring, archive search, current-information box, source playback, export, backup, restore, deletion, recovery, health, index repair, and application-lock controls remain available behind the Family Admin / diagnostics surface. Existing service-layer authorization and consent checks remain unchanged.

## CX02 participant state machine

`ParticipantConversationStateMachine` is a WinUI-independent state validator covering:

```text
Idle → Greeting → Listening → Thinking → Speaking → Listening
Listening → Clarifying / Offline / ErrorRecoverable / ConversationEnded
```

The shell uses the state to show `正在聆聽…`, `諗緊點樣回覆…`, `MEMENTO 正在講嘢…`, recoverable failure, and completed-conversation text. Automated tests cover the normal voice loop, ending from listening/speaking, recoverable provider failure, clarification return, and invalid transitions.

## Explicit limitations

CX01/CX02 do not claim automatic VAD, multi-turn microphone ownership, barge-in, live provider success, or physical microphone/speaker verification. Those require the later CX03/CX04 implementation and supervised target-machine gates. This checkpoint only changes the presentation boundary and adds a tested domain state contract.

The initial CX06/CX07 slice also adds bounded session context and a conservative current-information intent detector. Voice routing still needs a participant-facing answer composer and live search verification; external results remain time-bound and untrusted.
