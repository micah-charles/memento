# M03 evidence — provider boundary and bounded cloud path

**Date:** 2026-09-13  
**Status:** PARTIAL/BLOCKED pending credentialed live verification

## Scope

Keep local audio authoritative while allowing a future live voice provider to process only explicitly permitted content.

## Implementation

- `ConversationOrchestrator` accepts a finalized local audio path, privacy mode, and cloud consent. It rejects `PRIVATE_CONVERSATION` and `LOCAL_CAPTURE_ONLY`, request/session mode mismatches, missing consent, or missing local evidence before provider transmission.
- `IConversationProvider`, `ITranscriptionProvider`, and `IReasoningProvider` keep vendor-specific transport and model objects outside the domain/archive.
- `provider_interactions` stores provider, capability, model, model snapshot, request ID, timestamps, coarse usage, success, and content-free error metadata.
- `DeterministicConversationProvider` supports offline contract tests and is explicitly labelled as a test provider.
- `OpenAiTranscriptionProvider` provides an optional completed-audio HTTP adapter. It requires an injected credential, sends only a finalized local WAV, and does not persist credentials or raw error bodies.
- `OpenAiRealtimeWebSocketProvider` now provides an optional completed-turn Realtime WebSocket adapter with injectable transport, PCM16 chunking, explicit audio session configuration, text/audio delta parsing, output-size limits, and content-free provider failures. `RealtimeConversationOrchestrator` enforces `ConsentScope.LiveCloudConversation`, privacy mode, Source withdrawal, and post-call consent checks. The WinUI shell exposes that scope separately and persists returned 24 kHz mono PCM as a verified derived WAV for replay; a secure client-token broker and live account/device verification remain deployment work.
- `OpenAiRealtimeStreamingProvider` and `RealtimeStreamingSession` add a cancellable device-chunk path with a bounded queue, 48→24 kHz PCM downsampling, GA session configuration, response event parsing, input/output byte limits, and safe transport disposal. `RealtimeStreamingOrchestrator` applies the persisted live-consent and Source policy, records success/failure metadata, and stores returned PCM as derived WAV. The WinUI shell opens this path before capture when the separate live consent is selected; a secure client-token broker, live account exchange, and target microphone/output verification remain deployment work.
- When a live Realtime turn fails after the Source is finalized, the shell can enqueue the same Source for the durable transcription retry path if the participant also granted ordinary cloud-transcription consent; local evidence therefore has a bounded fallback without duplicating existing transcript work.
- `OpenAiResponsesProvider` and `BoundedVoiceConversationService` provide a turn-based fallback: a finalized local WAV and explicit Source ID are transcribed before a text response request, the initial transcript revision is persisted, and `store=false` is sent for Responses calls. Optional `OpenAiSpeechOutputProvider` produces derived speech bytes; `DerivedAudioStore` can atomically persist and hash them in the separate `derived_speech_assets` table, `WaveFileSpeechOutputPlayback` provides NAudio WAV playback, and the WinUI shell can replay the latest stored assistant output. Realtime PCM responses use the same derived store after WAV wrapping. Physical output-device verification and live provider validation remain future work.
- Successful and failed speech-output calls are recorded in `provider_interactions` with capability `speech_output`; generated audio is kept outside participant Source/Evidence records.
- `WindowsCredentialProvider` reads an optional API key from Windows Credential Manager through an injected target name; credentials are never committed or written to the SQLite archive.
- The WinUI shell keeps cloud consent separate from local capture consent, stores the session privacy mode accordingly, and only enables post-capture cloud processing for sessions created with explicit cloud consent. Provider or credential failures return a simple message while the local Source remains available.
- Speech and Source WAV playback mark cancellation before stopping the Windows output device, avoiding a stop-event race that could report interrupted playback as successful.
- The participant shell exposes all three privacy modes for the next recording; private and local-only modes disable cloud consent and current-information queries, and the service layer re-checks the persisted mode even if a caller supplies a forged request.
- Retryable transcription provider/network failures enqueue a durable `durable_transcription` job with a future retry time; missing local files and cancellation are kept out of the retry queue.
- Retryable response provider/network failures enqueue a durable `durable_response` job after the transcript revision is persisted. `DurableResponseJobProcessor` reuses that transcript, re-checks the latest cloud-consent event, and can persist optional derived speech output without retransmitting the original audio for transcription.
