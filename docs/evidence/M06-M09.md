# M06–M09 evidence — persistence, extraction, provenance, and entities

**Date:** 2026-09-13  
**Status:** IMPLEMENTED / AUTOMATED TESTED; live and admin verification pending

## M06 — conversation persistence

`conversation_jobs` records durable transcription work with explicit state, attempt count, retry time, and error. `ConversationSessionWriter` creates sessions and turns, queues work only after a local Source exists, and transitions jobs without deleting audio. Durable processors re-check cloud consent before upload, and policy-blocked jobs stop without an infinite retry loop. When a credential is available, the WinUI app starts the routed worker at launch so persisted work can resume after an ordinary restart.

## M07 — memory extraction

`EvidenceRecord`, `MemoryClaim`, and `EvidenceClaimLink` are separate durable records. Evidence can carry audio spans and extraction provider/model metadata. `MemoryExtractionService` writes candidates with `ClaimStatus.Candidate`; an extraction provider cannot silently create a reviewed canonical claim.

## M08 — provenance

`ProvenanceGraph.Validate` checks Source, transcript revision, Evidence, Claim, and link IDs plus allowed relationship names. An unconfirmed `AiInference` cannot be treated as a reviewed claim.

## M09 — vocabulary and entities

`PersonEntity`, `EntityAlias`, and `EvidenceEntityLink` provide additive identity context. Speaker-confirmed aliases retain the clarification event reference when available; old transcript and Source data remain immutable.
