# MEMENTO known issues and open questions

**Last updated:** 2026-09-14

These are deliberately visible. They are not reasons to invent a confident answer.

| ID | Issue/open question | Impact | Owner/gate |
|---|---|---|---|
| K-001 | The reviewed OpenAI sources do not guarantee Hong Kong Cantonese or mixed Cantonese/Mandarin/English accuracy. | High: core user experience and entity provenance. | Measure in M04 before pilot claims. |
| K-002 | Realtime audio prices are token-based; a universal minute conversion is not documented in the reviewed source. | High: operating-cost uncertainty. | Measure representative usage in M03 and update COST_MODEL. |
| K-003 | The Realtime path now has a bounded WebSocket device-chunk session and shell integration, but it still uses an API-key boundary; a secure short-lived client-token broker and production transport threat model are not selected. | High: privacy/security and deployment. | Choose and threat-model the broker/device flow before enabling live Realtime for a pilot. |
| K-004 | Shared Windows audio mix formats vary by device and configuration. | Medium: archive consistency. | Capture real device metadata in M02; preserve original PCM before conversion. |
| K-005 | Long-term backup destination, encryption-key recovery, and family succession are not designed in detail. | High: decades-long availability. | Design/test in M12–M14. |
| K-006 | Guest consent and multi-speaker attribution are deferred. | High if scope expands beyond one participant. | Keep disabled until a consent and diarization design passes review. |
| K-007 | “Corrected transcript” semantics need UX testing so corrections never appear to rewrite direct speech. | Medium: epistemic clarity. | Prototype in M05 and M11. |
| K-008 | SQLite FTS5 lexical search is implemented with a literal substring fallback for short Chinese queries, but ranking and tokenization quality still need a real Cantonese/Chinese corpus. | Medium: retrieval quality. | Evaluate the index and fallback against a consented redacted corpus before semantic search. |
| K-009 | OpenAI pricing, model aliases, endpoint retention, and platform docs may change. | Medium: stale planning claims. | Re-check before every milestone. |
| K-010 | Legal status varies by jurisdiction, purpose, household/commercial context, and guest situation. | High: consent/disclosure risk. | Obtain appropriate advice before pilot or sharing. |
| K-011 | Native WinUI visual/manual verification is unavailable in the current execution surface. | High: M01 gate cannot be honestly passed from this environment alone. | Run M01 on target Windows hardware with native GUI observation. |
| K-012 | M02's real Windows microphone path is implemented through NAudio but has not been exercised against a physical device or permission/disconnect failure. | High: audio is primary evidence and the M02 gate needs real-device verification. | Run the app with a consented microphone and fault-injection/physical interruption checks before pilot use. |
| K-013 | M03 now has provider-neutral adapters, Windows Credential Manager lookup, explicit cloud-consent UI, a bounded network path, and content-free persisted provider failure diagnostics, but no credentialed live exchange has been run. | High: the M03 gate requires observed provider behaviour and current account policy. | Configure a disposable credential and run a consented live test before pilot use. |
| K-014 | M04 validation uses synthetic fixtures only; it cannot establish Cantonese, code-switch, name, or latency quality for a real provider. | High: language quality is an empirical gate. | Collect a consented, non-source-controlled validation corpus and run the harness against the selected provider. |
| K-015 | M05 persistence and policy are deterministic, but the participant-facing clarification wording and interruption flow have not been observed with a real Cantonese speaker. | High: clarification must stay natural and avoid turning uncertainty into facts. | Run a supervised UX session and review the complete Source → revision → clarification → vocabulary chain. |
| K-016 | M06 now has a cancellable routed retry worker, persisted exponential backoff, and a five-minute stale-processing lease so jobs left in `Processing` by a crash can be reclaimed after restart. Bounded transcription and response failures enqueue durable jobs, retries re-check cloud consent, policy-blocked jobs stop without looping, and each bounded pass reports a simple UI status. Target-machine power-loss timing and visual notification behaviour remain untested. | Medium: offline sessions need reliable eventual processing. | Verify restart/retry timing and notification behaviour on target Windows hardware. |
| K-017 | M07 now has a deterministic fixture, an OpenAI structured-output adapter with local field validation, and a consent-gated durable extraction job; no live model quality or schema-validation corpus has been run. | High: candidate claims must remain reviewable and useful. | Configure a disposable credential and redacted evaluation corpus before promotion workflows. |
| K-018 | M09 now provides conservative review-only name/alias similarity suggestions; it never auto-links or promotes identity, and multi-speaker diarization remains unimplemented. | Medium: similar names and guests need stronger identity handling. | Review suggestions with participant/Family Admin confirmation and design multi-speaker consent/diarization in M11. |
| K-019 | M10 now has a deterministic fixture, an OpenAI Responses web-search adapter with an HTTPS domain allowlist, and a consent-gated WinUI query surface, but no live allowlisted call or source-freshness measurement has been run. | Medium: external answers need fresh sources without memory mutation. | Configure a disposable credential, choose the reviewed domain set, and measure source freshness/timeout handling. |
| K-020 | M11 now includes a Windows Administrators-role authorizer, candidate Evidence detail display, integrity-checked Source playback, and authenticated archive export/backup/restore controls, but account allowlists, elevation policy, physical output verification, and supervised Family Admin UX verification remain open. | High: family review and export are privileged operations. | Choose the family account policy and run supervised Family Admin UX verification. |
| K-021 | M12 now supports encrypted complete export bundles with media and manifest verification plus explicit password rotation, but key recovery, target-machine restore, and power-loss testing remain open. | High: an unrecoverable password or partial backup can harm a decades-long archive. | Define family-owned key recovery and run restore/power-loss drills before pilot. |
| K-022 | The optional OpenAI adapters now support completed-audio transcription, a turn-based text response, verified derived TTS storage, WinUI replay of the latest stored WAV, and WebSocket Realtime device-chunk streaming with a dedicated live-consent boundary. The shell can stream locally-written PCM during capture, commit after stop, and preserve the Source if the provider fails. A secure client-token broker, live account exchange, real microphone/output-device verification, and production interruption/latency review remain open. Credential Manager lookup exists for API-key use but has not been exercised with a real account. | High: a fully validated spoken conversation cannot yet be claimed. | Validate the integrated path with explicit cloud consent, a disposable credential, a real microphone/output device, and a target-machine transport review. |
| K-023 | The current project is deliberately configured as unpackaged (`WindowsPackageType=None`); enabling `GenerateAppxPackageOnBuild` without a package manifest fails configuration validation. A per-user install helper now creates a Start Menu shortcut, registers the app in the current user's Installed apps list, and provides a guarded self-cleaning uninstall helper that preserves archive data by default, but this is not an MSIX package. | Medium: signed package identity, enterprise deployment, and package-based servicing remain unavailable. | Choose a publisher identity/certificate and add a separately verified MSIX packaging project. |
| K-024 | `PRIVATE_CONVERSATION` is now enforced at every cloud conversation, transcription, speech-output, and memory-extraction service boundary, and the participant shell exposes it as a selectable local-only mode. An optional application lock stores only a salted verifier in the current Windows user's Credential Manager; an explicit recovery helper can clear that verifier after MEMENTO is closed, while target-machine unlock, recovery, and family policy still need supervised verification. | High: an unlocked Windows account could expose the local archive to another desktop user. | Choose a family-approved passcode policy, configure the lock, and run unlock/recovery tests before pilot use. |

## M00 limitations

No network-backed API call, Windows audio capture, crash simulation, real language corpus, or account-specific retention configuration was tested in M00. The documents record the source-backed design and label assumptions so those gaps can be addressed in later gates.
